1. ABSTRACT
--------------------------------------------------------------------------------
Ecom-Shop is an advanced, high-performance electronics and smartphone e-commerce 
platform and catalog management system designed to streamline online merchandising, 
multi-tier category organization, real-time inventory tracking, and dynamic pricing. 
Unlike conventional relational database architectures where rigid schemas struggle 
with the highly heterogeneous technical specifications of modern consumer electronics 
(such as varying camera sensors, processors, display refresh rates, and storage 
configurations), this project utilizes MongoDB as its primary NoSQL document-oriented 
database.

Python serves as the core data processing and business logic orchestrator, leveraging 
PyMongo—the official MongoDB driver—to execute robust document design patterns, schema 
validation, atomic CRUD operations, and multi-stage aggregation pipelines. The frontend 
provides a seamless, responsive storefront and an executive admin management panel 
for real-time catalog updates and stock adjustments. Pandas is integrated for tabular 
data handling, bulk record manipulation, and analytical summaries.

This report satisfies the academic requirements of CSE 494 (Intelligent NoSQL 
Databases), detailing document modeling, validation constraints, PyMongo integration, 
complex aggregations for sales and stock insights, comprehensive testing, and live 
deployment.


2. PROBLEM STATEMENT
--------------------------------------------------------------------------------
Consumer electronics and mobile devices represent one of the most dynamic sectors 
in retail. Traditional relational database management systems (RDBMS) impose fixed 
table schemas and extensive normalization (JOIN tables), which present significant 
drawbacks:
1. Heterogeneous Attributes: A smartphone has specifications like RAM, camera MP, 
   battery mAh, and 5G bands, whereas a laptop has CPU architecture, GPU memory, 
   and SSD slots. Modeling these in SQL requires excessive NULL fields or unwieldy 
   Entity-Attribute-Value (EAV) designs.
2. Hierarchical Categories: Categorization requires multi-level nesting (e.g., 
   Smartphones -> Flagship / Foldables / Budget, Laptops -> Ultrabooks / Gaming).
3. Real-Time Inventory & Price Volatility: Flash sales, discount rules, and rapid 
   stock changes demand low-latency atomic updates without table-locking overhead.
4. Administrative Bottlenecks: Without automated aggregation, computing category-wise 
   revenue, brand performance, and low-stock alerts becomes computationally expensive.

Ecom-Shop addresses these challenges by storing electronic products as flexible BSON 
documents in MongoDB, handled via PyMongo scripts, providing agile querying, sub-document 
nesting, and aggregation framework efficiency.

5. SYSTEM OVERVIEW & ARCHITECTURE
--------------------------------------------------------------------------------
The system architecture follows a clean, decoupled design:

[User / Admin]
       │
       ▼
[Interactive Web Client (Storefront & Admin Console)]
       │
       ▼  (HTTP / RESTful API Requests)
[Python Application Layer (Business Logic & Validation)]
       │
       ▼  (PyMongo Driver Protocol)
[MongoDB Atlas / Local Instance (ecom_shop_db)]
       ├── Collection: products
       ├── Collection: categories
       ├── Collection: orders
       └── Collection: inventory_logs
       │
       ▲  (BSON Queries / Aggregation Pipelines)
[Analytics & Reports Engine (Pandas Summaries & DataFrames)]

Data Flow:
1. Customer / Admin browses or updates products, categories, or prices.
2. The Python backend validates input constraints (non-empty fields, positive numbers).
3. PyMongo converts inputs into BSON documents and persists them to MongoDB collections.
4. When analytical metrics or catalog filters are requested, MongoDB executes aggregation 
   pipelines and returns structured documents.
5. Pandas organizes document results into tabular DataFrames for display and reporting.

7. VALIDATION RULES
--------------------------------------------------------------------------------
To maintain database integrity, strict validation is applied:
1. title        : Required, string, trimmed length between 3 and 150 characters.
2. sku          : Required, unique uppercase string identifier.
3. price        : Required numeric value (integer/float), strictly greater than 0.
4. costPrice    : Numeric value, must not exceed selling price (for positive margin).
5. stock        : Required integer, minimum value 0 (cannot be negative).
6. category     : Required string, must correspond to a valid active category.
7. status       : Enum strictly restricted to: ["draft", "published", "archived"].

MongoDB Collection-Level JSON Schema Validator (Sample):
{
  "$jsonSchema": {
    "bsonType": "object",
    "required": ["title", "sku", "price", "stock", "category", "status"],
    "properties": {
      "title": {
        "bsonType": "string",
        "description": "Product title must be a non-empty string"
      },
      "sku": {
        "bsonType": "string",
        "description": "Unique SKU is required"
      },
      "price": {
        "bsonType": ["double", "int", "long"],
        "minimum": 0.01,
        "description": "Price must be a positive number"
      },
      "stock": {
        "bsonType": "int",
        "minimum": 0,
        "description": "Stock count cannot be negative"
      },
      "status": {
        "enum": ["draft", "published", "archived"],
        "description": "Status must be either draft, published, or archived"
      }
    }
  }
}

9. AGGREGATION AND USEFUL REPORTS
--------------------------------------------------------------------------------
The MongoDB Aggregation Framework delivers high-speed analytics on the server side:

Report 1: Total Stock Count & Inventory Valuation by Category
-------------------------------------------------------------
db.products.aggregate([
  { $match: { status: "published" } },
  {
    $group: {
      _id: "$category",
      totalProducts: { $sum: 1 },
      totalStockUnits: { $sum: "$stock" },
      totalInventoryValue: { $sum: { $multiply: ["$price", "$stock"] } },
      averagePrice: { $avg: "$price" }
    }
  },
  { $sort: { totalInventoryValue: -1 } }
])
Explanation: Groups all published products by their primary category, computes total 
available units, calculates the total inventory monetary value in INR, calculates the 
average product price, and sorts from highest to lowest valuation.

Report 2: Brand Performance and Average Rating
----------------------------------------------
db.products.aggregate([
  {
    $group: {
      _id: "$brand",
      productCount: { $sum: 1 },
      avgRating: { $avg: "$rating" },
      minPrice: { $min: "$price" },
      maxPrice: { $max: "$price" }
    }
  },
  { $match: { productCount: { $gte: 2 } } },
  { $sort: { avgRating: -1 } }
])
Explanation: Identifies top-rated electronics brands offering at least 2 products, 
displaying their catalogue breadth and price range.

Report 3: Low-Stock Inventory Alert Pipeline
--------------------------------------------
db.products.aggregate([
  { $match: { stock: { $lte: 10 } } },
  {
    $project: {
      title: 1,
      sku: 1,
      brand: 1,
      stock: 1,
      urgency: {
        $cond: { if: { $eq: ["$stock", 0] }, then: "OUT_OF_STOCK", else: "LOW_STOCK" }
      }
    }
  },
  { $sort: { stock: 1 } }
])
Explanation: Extracts all items with 10 or fewer units in stock, tagging them with an 
urgency flag for warehouse restocking.


10. PYTHON AND PYMONGO INTEGRATION
--------------------------------------------------------------------------------
Below is the core Python script demonstrating PyMongo connection, indexing, CRUD 
operations, and aggregation reporting for Ecom-Shop:

```python
import os
from pymongo import MongoClient, ASCENDING, DESCENDING
from datetime import datetime

# 1. Establish MongoDB Connection via PyMongo
MONGO_URI = os.getenv("MONGODB_URI", "mongodb://localhost:27017/")
client = MongoClient(MONGO_URI)
db = client["ecom_shop_db"]
products = db["products"]

# 2. Ensure Indexes for Fast Searching
products.create_index([("slug", ASCENDING)], unique=True)
products.create_index([("sku", ASCENDING)], unique=True)
products.create_index([("category", ASCENDING), ("price", ASCENDING)])
products.create_index([("title", "text"), ("brand", "text")])

# 3. Create (Insert) Operation
new_product = {
    "title": "Apple iPhone 15 Pro Max",
    "slug": "apple-iphone-15-pro-max",
    "sku": "APL-IP15PM-256",
    "brand": "Apple",
    "category": "Smartphones",
    "subCategory": "Flagship Phones",
    "price": 149900,
    "costPrice": 125000,
    "stock": 25,
    "status": "published",
    "rating": 4.9,
    "created_at": datetime.utcnow()
}
result = products.insert_one(new_product)
print(f"Product inserted with ObjectId: {result.inserted_id}")

# 4. Read (Query) Operation
print("\n--- Flagship Smartphones ---")
for item in products.find({"category": "Smartphones", "price": {"$gte": 100000}}):
    print(f"- {item['title']} (₹{item['price']:,}) | Stock: {item['stock']}")

# 5. Update Operation (Bulk Price Adjustment)
update_res = products.update_many(
    {"category": "Smartphones", "brand": "Samsung"},
    {"$set": {"updated_at": datetime.utcnow()}, "$inc": {"stock": 5}}
)
print(f"\nUpdated {update_res.modified_count} Samsung items.")

# 6. Aggregation Execution via PyMongo
pipeline = [
    {"$match": {"status": "published"}},
    {"$group": {
        "_id": "$category",
        "itemCount": {"$sum": 1},
        "totalStock": {"$sum": "$stock"},
        "avgPrice": {"$avg": "$price"}
    }},
    {"$sort": {"totalStock": -1}}
]
print("\n--- Category-Wise Inventory Aggregation ---")
for row in products.aggregate(pipeline):
    print(f"Category: {row['_id']} | Items: {row['itemCount']} | Total Stock: {row['totalStock']} | Avg Price: ₹{round(row['avgPrice'], 2):,}")
```

Pandas Data Handling:
Pandas enhances the Python workflow by transforming raw PyMongo cursor query results 
directly into structured DataFrames:
```python
import pandas as pd

# Fetch documents from MongoDB into a Pandas DataFrame
cursor = products.find({}, {"_id": 0, "title": 1, "brand": 1, "category": 1, "price": 1, "stock": 1})
df = pd.DataFrame(list(cursor))

# Add calculated business column
df["TotalValue"] = df["price"] * df["stock"]

# Summary statistics
summary = df.groupby("category")[["stock", "TotalValue"]].sum().reset_index()
print(summary)
```
This enables rapid generation of CSV/Excel inventory reports and quick statistical 
summaries for inventory audits.

13. LIMITATIONS AND FUTURE ENHANCEMENTS
--------------------------------------------------------------------------------
Limitations:
• Advanced faceted search across deeply nested JSON specifications can become slow 
  without compound multi-key text indexes.
• Transactional multi-document consistency requires an active MongoDB Replica Set.

Future Enhancements:
• MongoDB Change Streams: Implement real-time inventory notifications via WebSocket 
  whenever a stock level changes.
• Vector Search: Implement MongoDB Atlas Vector Search for AI-driven semantic 
  recommendations (e.g., "phones good for night photography").
• Redis Caching: Introduce an in-memory Redis cache layer in front of PyMongo for 
  ultra-high-frequency read requests during flash sale events.
